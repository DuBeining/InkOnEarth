# InkOnEarth

项目最初的设想是在地图上显示旅行轨迹，也就是选择两个城市并连线，形成一个轨迹图。<br>
其中，个人认为CartoDB Voyager提供的地图格式相对美观，但是其需要api，可以在[Stadia Maps](https://stadiamaps.com/)中获得。<br><br>

在制作的过程中，我想到一个点：是否可以用这些轨迹组成特定的图案，比如汉字？（嗯...听起来不错）<br>
于是我在原来的基础上加以改进，首先是对汉字进行处理，这方面包括导入汉字、拆解并提取汉字笔画、采样连接。<br>
最开始使用的字体是开源楷体，但是经过试验发现，其双轮廓对于城市匹配的判定操作极其不友好，所以最后考虑使用[单线中轴](https://cdn.jsdelivr.net/npm/hanzi-writer-data@2.0/${encodeURIComponent(char)}.json)（Medial Lines）字体。<br><br>

在字形调整的过程中，还发现一个问题，使用等距采样的时候，很多笔画会产生弯折，非常不美观。<br>
Gemini告诉我，可以采用道格拉斯-普克（Douglas-Peucker）算法，只保留拐点，在弧线处进行插值以维持平滑。<br>
在实际交互中，用户还可以调整框架的“平直度”，调整笔画的弧度，也就是插值点的阈值。<br><br>

之后，就需要处理城市了，我是选择了中国(34.0,113.5)作为中心，不过实际操作中可以进行调整。<br>
对于中国各地级和县级区划的名称和经纬度，可以在[阿里云数据库](https://geo.datav.aliyun.com/areas_v3/bound/all.json)中得到json文件，导入到项目中。<br>
在进行映射的时候，为了防止纬度上的拉伸，用墨卡托投影进行了矫正。<br>
以及，为了防止采样点过于密集，加入了过滤的机制。<br><br>

为了增强可视化效果，我保留并改进了最初的html文件(index.html)，这样可以同时显示多个汉字，能够展出一句话。<br>
前面的操作以及数据的导出需要在 index+.html 里完成。<br><br>
